# 聊天请求关联契约（2026-10-06）

## 群图片（2026-10-19，0.1.15）

新增登录能力 `group_images=true`，需同时支持 `group_chat`。客户端仅协商后开放群图片
发送、截图和转发；未协商时保留文字与既有图片接收能力，提示升级服务器。
沿用 `msg_type=1`、1050/1052/1054 资源协议及可靠发送，不改变旧编号和含义。
群上传的 `recipient=0, thread_id=<实际群ID>`；资源 ID 身份摘要包含 group 范围及群 ID，
资源元数据不可改绑。就绪记录使用独立群范围，服务端不接受私聊资源直接用作群授权，
也不接受跨群或群资源直接用于私聊。聊天写入仍在 DAO 事务中重查群状态和成员资格。
ResourceServer 每次受保护读写通过仅回环的独立 RPC 核验实时权限，详见
[资源服务说明](../../ResourceServer/README.md)。本轮不需要生产 DDL 或导入整库 SQL。

## 共同群聊查询（2026-10-18）

登录能力 `common_groups=true` 表示支持 `1060/1061 op=common`。
请求为 `{op:"common", friend_uid:<正整数>, after:<非负整数，默认0>, request_id:...}`。
身份来自已认证会话，忽略客户端伪造的 uid。目标必须为好友且不能为自己。
成功结果仍使用现有 `group` 字段封装查询页：
`{friend_uid, groups:[{thread_id,name,owner_uid}], next_thread_id, has_more}`。
只返回双方当前均有成员记录且 active 的群，按 thread_id 递增，每页最多 50 个；
只在存在第 51 项时声明 has_more。客户端以 next_thread_id 请求下一页，刷新从 0 开始。
与其他群操作复用相同请求关联和错误机制；查询响应不作为单个群的资料更新广播。
不允许非好友探测群列表，不返回群成员名单、聊天内容或私聊会话。
客户端支持失败重试和关闭取消；缺少能力位时提示更新服务器，不发送探测请求。

## 视频扩展（2026-10-18）

登录能力 `video_call=true`。复用 1070/1071 控制和 1072/1073 Opus 音频，新增
1074/1075 视频发送/接收；统一受认证登录、双用户占用、通话 ID 与租约约束。
视频邀请、接听、保活、音频和视频均携带 `video=true`；未提供该字段表示语音，
通话创建后不能改变类型，服务端拒绝缺少视频同意的接听。拒接、取消和结束始终允许
所属通话释放资源。`camera` 控制额外携带布尔 `enabled`，通知清除或恢复对方画面。
视频消息包含 call_id、peer、独立递增 seq、image（JPEG Base64，最多 8000 字节）；
编码图像最多 6000 字节、320×240、每方向每秒 8 帧、最多突发 2 帧，不与音频共享序号。
JPEG 格式和头部尺寸在客户端解码前核对，超大帧、旧会话、重放、未接通、语音通话或
该方向摄像头已关闭时拒绝视频。媒体成功不 ACK，限流和积压直接丢帧。
跨节点 RelayVoice 增加 video 标记（Proto 字段 5）；仅 loopback，必须同时升级两个节点。

## 语音扩展（2026-10-18）

登录能力 `voice_call=true`；1070/1071 为控制请求/事件，1072/1073 为音频发送/接收。
控制字段：`call_id`（32 位小写 UUID 十六进制）、`peer`（对方 UID）、`action`
（invite/accept/reject/cancel/end/ping）。服务端从已认证连接取发送人，忽略伪造身份。
1071 含 `error`，通知对端带 `incoming=true`，`peer` 改为发送人；调用方的合法
`request_id` 原样回传。语音有自身按 call_id 编排的超时，不共用普通请求的单槽重试。
音频字段：call_id、peer、递增正整数 seq、audio（单声道 48kHz/20ms Opus base64，
原始至多 512 字节）。成功音频不 ACK，不允许重发；非法状态拒绝，限流丢弃。
错误码 1021 忙线、1022 离线、1023 无效通话/状态/序号、1024 本地传输不可用、1025 限流。
来电租约、双端保活、当前登录绑定和信任边界见 `../services/README.md`。

原 2026-10-06 请求关联改动是兼容性 JSON 扩展，不更换 `uint16 消息编号 + uint16 正文长度 + JSON` 大端帧头，不改当时的消息编号、业务 ErrorCodes、SQL 或 protobuf；语音新增项以上述扩展为准。

## request_id 与能力协商

`TcpMgr` 为受跟踪请求的每次发送生成新 UUID 字符串 `request_id`，包括取消/超时后的再次请求。服务端允许省略该字段；若提供，必须是非空字符串，UTF-8 字节长度不超过 64。业务字段校验失败仍回传合法标识；非法标识不回传。

成功登录回包新增 `request_correlation=true`。客户端连接重置时清除此能力；收到成功登录后才启用严格模式。受跟踪回包包含标识时，无论是否协商，都必须匹配当前待处理尝试。严格模式下无标识回包也忽略，保留当前超时；不允许旧回包停止新请求的定时器。

登录本身尚未协商：包含标识则核对；不包含标识允许按旧逻辑处理。断开连接会清空待处理请求和能力。

| 流程 | 关联方式 | 本次边界 |
| --- | --- | --- |
| 登录、搜索用户、好友申请/接受/删除/标签、资料更新、会话列表、创建私聊、历史分页 | 每次尝试的 `request_id` | 每个请求编号仍只有一个待处理槽位，不是同类型任意并发请求队列 |
| 文本/图片聊天元数据及确认 | 消息 `unique_id`、会话 ID | 沿用 UUID 去重与手动重试，不改成按传输标识持久化 |
| 心跳及好友快照 | 当前连接、`friend_snapshot_id` | 不进入通用请求定时器；服务端也能回传调用者提供的合法标识 |
| 头像加载 | UID、已有连接/调用生命周期检查 | 不进入通用请求槽位；不新增头像服务端幂等协议 |
| 好友/消息推送、踢下线 | 通知数据中的业务身份 | 不伪造客户端请求关联，不消费待处理槽位 |
| 独立资源连接 | 文件 ID、块偏移、UID/token、原顺序/重试规则 | 不增加本契约字段，不改变上传/下载编号或窗口 |

服务端在回包适配层统一回传，而不是让每个业务服务自行生成标识。历史分页的 JSON 大小检查计入标识，心跳快照在回传标识后再次核对上限。

## 兼容与限制

- 旧客户端 → 新服务端：标识可省略，原业务字段和消息 UUID 保留。
- 新客户端 → 新服务端：成功登录后，受跟踪响应必须匹配当前标识；迟到成功包和错误包均忽略。
- 新客户端 → 旧服务端：旧服务端未声明能力时，缺少标识的响应沿用原 thread_id/other_id/friend_uid 核对。标签操作本来就要求回传标识，继续保留该要求。极旧、不支持标签关联的服务端不保证标签兼容。
- 旧兼容路径不能可靠区分同一连接中同类型、同目标的重试；升级客户端和两个节点、重新登录后才能依赖严格关联。
- `request_id` 只是匹配当前响应，不是消息去重键、分布式事务 ID、身份凭证，也不是服务端取消。已开始/提交的 SQL、文件或 RPC 不会因为客户端取消槽位而撤销。
- 解析/标识不合法返回原 JSON 错误；未登录请求优先走认证拒绝，合法包络的标识照常回传。未知消息编号和连接级错误不保证业务回包。
- 本次不增加 TLS、持久通知补偿或真实跨节点送达确认，也不解决登录初始好友列表已有的整体正文大小限制。

## 本轮验证

两个实际节点 EXE 的隔离回归覆盖合法标识的参数错误/未登录拒绝、64 字节边界、非法标识和非对象 JSON。客户端生产对象的 QtTest 覆盖同目标取消重发后的旧成功/错误包、严格模式缺失标识和旧服务端历史加载。完整构建、测试配置及未验证边界见 [架构加固进度](architecture-hardening-20261006.md)。


## 群聊（1060 / 1061）

登录成功声明 `group_chat=true`。客户端连接关闭即清除此能力；旧服务器没有该标记时，
群管理入口说明服务器尚未升级，不发送未知操作。
1060 走现有 request_id 关联和 15 秒请求超时，同一时刻只有一个群操作槽位。

| op | 请求字段 | 权限 |
| --- | --- | --- |
| create | name、members（好友 UID 数组）、creation_key | 已登录用户；自己自动加入 |
| info | thread_id | 当前成员 |
| rename | thread_id、name | 群主 |
| add | thread_id、member_uid | 群主邀请自己的好友；最多 32 人 |
| remove | thread_id、member_uid | 群主；不能移除群主 |
| transfer | thread_id、member_uid | 群主；目标必须为其他当前成员 |
| leave | thread_id | 普通成员，群主需先转让 |
| disband | thread_id | 群主 |

成功返回 error=0、op、group；group 含 thread_id、name、owner_uid，info/创建/管理响应另含
members: [{uid,name}]。退群和解散返回 group:{thread_id,removed:true}。
错误码 1018=无群成员权限，1019=群主不能直接退群，1020=32 人上限；格式错误沿用 1001。
name 上限为 UTF-8 的 64 字节，不接受控制字符；creation_key 为 1–64 字节 ASCII 字母、数字或连字符。
创建超时重试保留 creation_key 和初始参数，同一个 key 不得用于不同内容。

会话列表 1026 中群条目 type="group"、user1_id=user2_id=0，并有 group 摘要。
群消息仍使用 1017/1018/1019：touid=0，thread_id 为群会话 ID，fromuid 必须匹配当前会话，
text_array 的 UUID 和去重规则不变。群图片（msg_type=1）当前拒绝。
1019 携带 group 摘要，可含 member_names（以 UID 字符串为键的发送者显示名缓存），
群管理 info 的完整成员列表也可补齐显示名。客户端优先显示自己的好友备注。
群历史复用 1029/1030，并在服务器检查 active 群及当前成员身份。

本地复用加密的聊天记录库；群资料保存在附加的 group_profiles 表，原私聊表不重建，
旧库自动补表，不迁移到普通明文 SQLite。成员撤销后移除会话入口和发送队列，保留已有本地数据。
群会话和权限在完整分页刷新后核对，默认 10 秒；实时通知可能先于会话列表到达。

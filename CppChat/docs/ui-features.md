# 界面功能

聊天、通讯录与输入工具的界面和行为说明。项目目录见 [项目说明](project-guide.md)。

## Windows 深浅色外观（2026-10-19，v0.1.17）

- 默认跟随 Windows 的应用颜色模式；侧栏“设置 → 外观”可选择跟随系统、浅色或深色。
  保存后立即更新现有窗口，保留草稿、输入选区和笔记，重启后记住本机选择。
- `ThemeController` 负责系统/偏好变化，`ThemeManager` 统一加载语义颜色、QPalette、QSS、
  字体和 Windows DWM 标题栏；业务窗口不各自判断深色。颜色来自 `style/tokens-dark.json`，
  复用现有 Qt Widgets/Fusion 样式，不增加依赖。图像、头像和视频内容不改色。
- 聊天、登录/注册/重置、联系人、记录、设置及弹窗使用同一主题；单色图标、选中文字、
  输入框和附件占位预览补齐深浅色适配。原生文件选择器仍遵循 Windows 自身设置。
- 复用 Qt 官方 [QStyleHints::colorScheme](https://doc.qt.io/qt-6/qstylehints.html#colorScheme-prop)
  和 [Windows 深色模式说明](https://www.qt.io/blog/dark-mode-on-windows-11-with-qt-6.5)，
  对 Qt 6.4/Unknown 情况只读查询 Windows AppsUseLightTheme，并监听主题事件。
  不修改 Windows 注册表或全局主题。标题栏参考微软
  [DWM 主题文档](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-windows-themes)。
- 新增密码可见图标复用 Lucide 0.468.0 的 eye，保留 ISC 许可；来源及改色范围见
  `Resources/icons/README.md`。沿用当前 Qt Kit，无新库的许可、ABI 或维护负担。
- 自动验证覆盖保存/重启加载、系统颜色信号、手动覆盖、重复切换、字体不重复注册、
  真实窗口的即时换色和草稿保留；另外在 Windows 原生平台查询 DWM 深色/标题栏属性并截图。
  系统变化用 Qt 信号注入，未替用户切换 Windows 设置；Qt 6.4 回退路径未在旧 Kit 上实测。

## 本机设置和记录导出（2026-10-19，v0.1.17）

- 侧栏“设置”打开本机设置中心，可选择 Enter 或 Ctrl+Enter 发送，保存后同时作用于已打开的
  聊天编辑器。Enter 模式下 Shift/Ctrl+Enter 换行；Ctrl+Enter 模式下 Enter 换行，
  Shift+Enter 始终不发送。按键自动重复和输入法预编辑期间不会触发发送。
  设置还支持关闭/开启启动时检查更新，手动“立即检查更新”继续使用已有更新验证流程。
  恢复默认只修改选项，需保存才生效；关闭不保存。当前版本显示实际编译版本。
- 本机选项保存在 `RuntimePaths::preferencesDirectory()/client.json`，仅包含格式版本、发送快捷键
  和自动检查更新开关，不包含账号、服务器地址或密码；不修改网络/TLS 配置。
  原子写入成功后才更新内存并通知编辑器，失败保留旧值和界面输入。格式损坏使用默认值并提示，
  遇到更高格式版本拒绝覆盖，避免降级破坏设置。开机启动和锁定功能仍未新增；主题切换见上节。
- 全局及单会话记录窗口“导出记录”按当前关键词、会话、类型、日期导出所有匹配页，
  **仅包含已确认消息**，支持 UTF-8 `.txt` 和 `.json`。选择目标文件时显示明文提示；
  JSON 只写出会话名称/ID、消息 ID、发送人 UID、时间、类型、正文，图片和语音只写资源 ID，
  不下载附件、不导出凭据或完整数据库，不提供重新导入。最多 10000 条、32 MiB，
  超限要求缩小筛选范围，不生成看似完整的截断文件。
- 导出期间冻结筛选，按钮可取消；关闭窗口、切换账号、本机删除/清空或相关群资料/权限变化
  会中止，已有目标文件保留。按首轮本机行号上限分页，之后新入库消息不混入，
  **不是跨页数据库事务快照**，已有行的确认状态更新以读取时为准。
  空会话范围导出空集合，仍受本机删除边界和当前权限约束。
  禁止覆盖内部账号数据/设置及符号链接；其他既有文件使用文件选择器的覆盖确认。

设置持久化和导出复用现有 Qt Core 的 [QSaveFile](https://doc.qt.io/qt-6/qsavefile.html)，
关闭直接覆盖回退，只有完整成功时提交；导出分批使用现有 `ChatStore` 工作线程查询和
`HistoryCursor`，GUI 线程每次只写一页，沿用 `ClientUpdateService` 的有界写文件方式。
消息按键使用 [QKeyEvent](https://doc.qt.io/qt-6/qkeyevent.html) 和
[QInputMethodEvent](https://doc.qt.io/qt-6/qinputmethodevent.html)；跨页语义参考
[SQLite 隔离说明](https://www.sqlite.org/isolation.html)，不把多个独立查询声称为事务快照。
使用既有 Qt 6.12/SQLite 锁定依赖和许可，不新增第三方库，不复制外部源码；接口适用于 Qt 6.4。
`client.settings_export` 使用隔离加密库、本机临时文件、实际编辑器/窗口和非原生文件选择器，
覆盖保存失败、格式升级保护、实时按键/输入法、导出筛选/分页/上限/取消/重试、权限变化、
窗口销毁与账号切换，不替代真实中文输入法、多屏或远程文件系统的人工验收。

## 独立聊天区域和全局记录（2026-10-19，v0.1.17）

- 会话右键“独立窗口显示”将当前聊天页移到一个独立窗口；主界面可继续使用通讯录、收藏和
  侧栏。切换会话仍在该独立窗口显示，关闭、Escape 或“返回主窗口”把页面放回原处。
  **当前是一个可分离的聊天区域，不是每个联系人同时开启一个编辑窗口。** 页面、草稿缓存、
  可靠发送队列和音视频通话服务均沿用原实例，不创建重复处理器。草稿在移动前保存，
  窗口标题随备注/群名称更新；切换账号会收回并清空聊天页。未读判断跟随实际聊天窗口焦点。
  聊天页、图标和滚动条样式按 `ChatPage` 组件作用域匹配，不依赖嵌入主窗口的祖先结构。
- 侧栏“聊天记录管理”打开所有可用会话的本机历史，支持会话范围、关键词、图片、语音、链接、
  日期筛选和每页 50 条的前后翻页。全局按消息时间和本机唯一行号倒序，单会话仍沿用消息 ID
  游标；来源按钮打开原会话，不声称定位到某条历史消息。文本按字面匹配 `%`、`_` 和反斜杠。
  查询只包含当前账号仍可访问的好友/群，空权限集合不会扩大为所有记录；切换账号清空并关闭，
  删除好友/退群后使旧结果失效。会话隐藏不等于清空记录，隐藏的可用会话仍可在此搜索。
- 本机清空和单条删除标记继续生效；这里只查询已经保存在本机的消息，不请求导出云端数据，
  批量删除/附件文件管理尚未提供；导出见上节。不改变数据库版本，不增加服务器接口。

复用项目已有 `ChatPage`、`ChatHistoryDialog`、`ChatStore` 和消息展示组件，新增窗口只负责
托管同一个页面。按 [Qt QSplitter 的控件替换与所有权规则](https://doc.qt.io/qt-6/qsplitter.html#replaceWidget)
及 [QDialog 非模态窗口生命周期](https://doc.qt.io/qt-6/qdialog.html)适配，使用现有 Qt 6.12
接口（兼容项目 Qt 6.4 最低版本）。全局查询复用现有加密 SQLite 驱动的
[内置 JSON 表函数](https://www.sqlite.org/json1.html#jeach)，通过绑定的 JSON 会话 ID 集合筛选，
避免拼接用户输入和大量 SQL 占位符。没有引入新依赖、复制外部源码或改变上游许可。
检索的 [qTox 原仓库](https://github.com/qTox/qTox)已归档且采用 GPL-3.0，本轮仅参考其独立窗口
使用场景，不复制其实现；采用当前项目的 Qt 官方 API 和回归测试验证。

`client.workspace` 验证真实入口、同一编辑器/发送器、草稿保存、关闭/Escape 收回、账号切换、
全局权限/删除边界/分页、两个历史窗口并发查询和深色系统调色板。
本轮仅构建本地开发程序；真实桌面多屏、DPI、设备通话验收及安装包发布另行验证。

## 通讯录管理、笔记和消息提醒（2026-10-19，v0.1.17）

- 通讯录管理入口打开真实好友表格，支持按账号、昵称、备注、标签、UID 搜索，组合标签和
  星标筛选、排序、查看资料与设置星标。备注/标签编辑复用 `ApplyFriend` 和既有服务器协议，
  服务器确认后刷新；断线时禁用编辑，删除好友仍使用资料页已有的确认流程，不提供假批量删除。
- 收藏页“写笔记”和聊天加号菜单“写笔记”均打开本机笔记中心。可新建、搜索、分页查看、编辑、
  另存、删除和发送给好友/群聊；发送复用既有目标选择和可靠消息队列，保留聊天草稿。
  纯文本标题最多 80 个 UTF-16 单元、正文最多 32 KiB UTF-8、每账号最多 1000 篇。
  两个窗口编辑同一篇笔记时按 revision 检查，旧版本不能覆盖新内容；保存失败保留输入，
  可以另存。关闭未保存笔记默认保留修改，切换账号则清空并关闭旧窗口。
- 已确认消息右键“提醒”可选择未来一年内的时间；收藏页“提醒事项”可查找摘要、修改时间、
  完成/取消及打开原会话。摘要独立保存，清空聊天不移除笔记、收藏或提醒。
  每账号最多 500 条未处理提醒，完成/取消后从提醒中心移除，不保存完成历史。
  **仅在客户端登录运行时每 15 秒检查**；退出后不启动后台服务，重登会显示未处理到期项。
  到期状态先落盘，再打开应用内提醒中心并闪烁窗口；一次登录内不反复弹出同一时间的提醒，
  改期后可再次提醒。没有系统托盘推送、手机通知、精确到秒的唤醒或原消息位置跳转。

新增内容均在当前服务器/账号的既有 SQLite 库中，Windows 沿用加密连接、DPAPI 和附件保护，
其他平台沿用已有存储策略；不写入账号无关的明文配置。
完整建表脚本增加 `local_notes` 和 `local_reminders`，
本机库幂等升级到 v5，不重建原表；保留消息、游标、草稿和收藏，不修改服务器 MySQL。
**升级后的库不能由旧版客户端打开**，不应通过修改 `user_version` 绕过保护。
本轮测试使用隔离账号，未打开真实业务数据库，也没有发布或部署。

存储操作在 `ChatStore` 工作线程中，笔记保存使用单条带版本条件的 SQL；
`ReminderService` 只管理账号生命周期和定时检查，窗口负责编辑与展示，页面不执行 SQL。
复用已锁定的 Qt 6.12 Widgets/SQL、SQLite3 Multiple Ciphers 2.6.1 / SQLite 3.54.0，
未引入新的第三方库或复制外部业务源码。参考并适配
[Qt 筛选代理模型](https://doc.qt.io/qt-6/qsortfilterproxymodel.html)、
[日期时间编辑器](https://doc.qt.io/qt-6/qdatetimeedit.html) 和
[SQLite RETURNING 的提交语义](https://www.sqlite.org/lang_returning.html)。
使用的接口兼容既有 Qt 6.4 Linux Kit；实际构建/验收平台以本轮报告为准。

`client.organizer` 覆盖真实 UI、加密库升级、写盘失败、旧版本编辑冲突、容量和字节限制、
字面搜索/分页、到期状态失败回滚与重登恢复、去重通知、账号/服务器隔离，以及真实回环 TCP
备注保存。截图和系统深色调色板测试不替代真实 Windows 多屏/缩放验收。

仍待实现的核心项包括文件消息传输、按联系人同时多开编辑窗口、语音转文字/语音搜索、翻译、群通话、
朋友权限、聊天文件管理、历史批量删除和锁定等侧栏操作。发现页、朋友圈、视频号、小游戏、
小程序及手机联动仍为占位，需要分别定义业务范围；本批不将这些入口算成已实现。

## 本机会话管理（2026-10-19，v0.1.17）

- 会话右键菜单和聊天设置里的“消息免打扰”保持一致，并显示静音图标。消息仍接收和落盘，
  保留未读状态，但不显示该会话的未读红点，也不计入聊天侧栏红点；取消免打扰后恢复提示。
  当前项目没有消息声音、系统通知或推送，此功能只控制现有红点提醒，不屏蔽来电。
- “不显示”仅隐藏列表项，保留聊天记录、草稿、置顶、免打扰和待确认发送。
  隐藏按当时最新确认消息 ID 记录边界，普通刷新和旧记录补拉不会让它重新出现；
  更高 ID 的新消息（含其他设备发送）或从通讯录、搜索、群列表主动打开时恢复显示。
- “删除本机会话”默认取消，确认后清空本机已确认记录并隐藏列表项。
  复用既有 SQLite 事务、清空边界和同步游标，旧消息不会因补拉或重登重新出现。
  服务器记录、好友/群成员关系、草稿、收藏及共享附件缓存保留，不发送删除好友、退群或撤回请求。
  有待确认消息时拒绝删除；确认期间新出现待确认消息，也在数据库事务内检查并拒绝。
- 新增的免打扰/隐藏偏好按服务器地址摘要和账号隔离，退出重登保留；保存失败不会假装改变列表。
  本机历史与偏好是两个存储：若记录已清空但隐藏偏好写入失败，保留可见会话并明确提示部分成功。
  原有置顶/手动未读继续使用已有偏好格式，不在本批迁移。

职责沿用 `ConversationPreferences` 持久化、`ConversationSection` 管理列表交互、
`ChatDialog` 处理当前导航及未读提示、`ChatStore` 处理事务。没有新建数据库表或网络协议，
不引入新依赖；既有 Qt 6.12 API 在 Linux Qt 6.4 也可用，本批实际执行平台以测试记录为准。
复用 [Qt QSettings 原子同步及状态检查](https://doc.qt.io/qt-6.12/qsettings.html#sync)，
并参考 [Matrix 的按房间通知规则](https://spec.matrix.org/latest/client-server-api/#push-rules)
将“消息是否收到”和“是否提醒”分开；未复制外部业务代码或引入其协议栈。
`client.conversations` 用隔离账号和加密库覆盖菜单、开关、未读提示、重登、草稿、补拉、
写盘失败、待确认并发及确认期间切换账号，不使用生产数据。

  摘要最多 1024 个 UTF-16 单元、8 行，截断时显示省略号并保留完整代理对。
  这是可编辑的纯文本引用，沿用现有发送协议；暂不包含原消息 ID、跳转或结构化回复关系。
- 已确认消息可经明确确认“仅从本机删除”，默认选择取消。提交成功后才移除界面和搜索结果；
  删除失败回滚并保留消息。不会发送撤回请求，不影响服务器或其他设备。
  本机 SQLite v2 保存会话/消息 ID 删除标记，防止重登、历史补拉或重复通知复活消息；
  同步游标照常前进。待确认消息不能删除，避免把本机隐藏误当成取消发送；共享图片缓存保留。

## 表单校验

登录、注册、重置密码共用 `common/formfeedback` 管理提示，输入规则继续使用
`common/inputvalidator`。Qt Creator 工程中的源码和头文件已归入 `common`。

实现参考以下高星项目的实际源码（2026-10-03 查询，星数约为 3.3 万和 2.8 万）：

- [Telegram Desktop](https://github.com/telegramdesktop/tdesktop)：
  [密码登录页面](https://github.com/telegramdesktop/tdesktop/blob/d8594c011756265de4385408540bd9f7c787a003/Telegram/SourceFiles/intro/intro_password_check.cpp)
  将输入变化连接到 `hideError()`，提交时检查当前输入，服务端回调处理请求错误。
- [Element Plus](https://github.com/element-plus/element-plus)：
  [FormItem](https://github.com/element-plus/element-plus/blob/dev/packages/components/form/src/form-item.vue)
  为每个字段维护校验状态和消息，`clearValidate()` 清理本字段的状态。

本项目按上述交互和状态管理方法独立实现 Qt 适配，没有复制上游源文件，
没有引入 Telegram 的响应式框架或 Vue 依赖。验证码结果与字段错误的分离、
按界面顺序显示首条错误，是适合本项目现有单个提示标签的处理。

### 行为

- 登录页在邮箱或密码框中按主键盘 Return / 数字键盘 Enter，与点击登录使用同一校验和请求流程；请求期间登录按钮禁用，回车不会重复提交。嵌入主窗口的登录页复用 Qt 6.12 的 [QLineEdit::returnPressed](https://doc.qt.io/qt-6/qlineedit.html#returnPressed) 信号触发登录按钮，关闭按钮的自动默认行为，避免重复提交和注册按钮抢占回车。
- 输入框失去焦点时校验；尚未校验的字段在初次输入时不立即报错。
- 已经校验过的字段在内容变化时重新检查，旧错误不等到下一次点击提交才消失。
- 点击提交检查全部字段，按界面顺序显示第一条错误，并聚焦该输入框。
  所有无效字段显示红色边框；输入改正确后恢复原有边框。
- 密码变化时重新检查已经填写或校验过的确认密码。
- 本地字段错误优先显示；验证码发送成功/失败等请求提示单独保存。
  修正无关字段后，仍能看到请求结果；改变关联字段或重新发起请求时清理旧结果。
  验证码发送结果只关联邮箱，注册、登录、重置密码结果关联该表单的全部字段。
- 返回登录、重新注册或退出登录时，通过统一的 `reset()` 清理字段状态和提示。

### 人工回归检查

本次仅做源码和主题静态检查，未编译或运行客户端。编译后重点检查：

1. 三个页面留空提交，逐项修正，提示始终按本页面字段顺序切换。
2. 同时填错用户名、密码，再修正密码，不应重新出现已经修正的用户名错误。
3. 先出现密码格式错误，再获取验证码；修正密码后仍应显示验证码请求结果。
   修改密码不清除验证码结果，修改邮箱会清除。
4. 两次密码一致后修改原密码，确认密码立即提示不匹配；修正后恢复。
5. 服务端返回失败后，离开一个内容未变的合法输入框，失败提示仍保留。
   修改关联输入或再次发送请求后，旧结果被清理。
6. 返回登录再进入注册或重置密码，旧提示和红色边框已清理。

### 导航与数据协作

- `SwitchSection()` 同步当前模块、页面栈和侧栏选中按钮，使用页面指针，不依赖数字索引。
- 通讯录中点击发消息：`sig_open_chat → ChatDialog::OpenChat → SelectThread`。
- 好友申请放在左侧“新的朋友”分组；`sig_open_friend_apply` 打开右侧单条申请，
  已添加且仍为好友的记录复用好友资料，不在详情栈重复列出全部申请。
- 联系人搜索仅搜索好友并打开资料；聊天搜索继续搜索好友、会话与已加载消息，按原协议补齐历史。

- `UserMgr`、`TcpMgr` 继续承载现有共享数据与传输，模块不直接访问兄弟模块的控件。

### 异步响应与会话边界

创建会话请求记录 `_createNavigationRevision`。用户切换模块、选择其他会话或打开
个人资料窗口后，导航版本改变。响应始终可以登记会话、刷新列表和加载历史，但只有
版本一致且仍处于聊天模块时才打开会话，避免迟到的响应抢走用户当前页面。

新消息只更新数据、摘要与未读状态，不切换模块。当前会话只有在聊天模块可见、
主窗口处于激活且非最小化状态时才按当前客户端规则清除本地未读标记；窗口恢复
激活后会重新检查。该标记是客户端状态，不是服务端已读回执。

`ResetSession()` 关闭子弹窗，重置四个模块及个人资料、分页队列和未读状态，回到
聊天模块。导航版本不回退，失效的导航意图不会因重置复用旧版本号。

<a id="contact-tags"></a>

## 联系人标签

标签归属于当前账号与某位好友的关系，例如 A 为 B 设置的“同学”只向 A 展示。
它不属于 B 的个人资料，不会通过好友申请通知公开给 B。

### 使用

- 发起好友申请时，选择或输入标签，随申请保存到 `friend_apply.tags`。
- 接受申请时，可设置自己的标签。创建双方好友关系的同一事务，将申请者的
  标签复制到申请者的 `friend.tags`，把接受者选择的标签写入接受者的好友记录。
- 通讯录 → 联系人资料 → 标签，可以查看已保存内容；没有标签显示“未设置”。
- 联系人资料右上角菜单 → 设置标签，可添加、删除和清空已有标签，再点击保存。
- 客户端收到成功回包后才更新联系人数据；失败保留原标签，并允许重试。
- 重新登录时，`friend_list[].tags` 从数据库恢复；删除好友会一同删除该好友关系的标签。

每位联系人最多 12 个标签；每个标签最多 128 个 UTF-8 字节。服务端会检查
类型、数量、长度，去除首尾空白及重复项，拒绝空名称和控制字符。

### 部署

新机器执行 [完整建表脚本](../../database/mysql/schema.sql)，其中 `friend_apply`、
`friend` 已包含可空的 `tags` 字段，用于存储 JSON 数组文本；NULL 按空数组读取。
两个聊天节点共用同一数据库时只需初始化一次。脚本用于新库初始化，
不会自动修改已存在表的字段。

随后重新编译客户端、ChatServer 和 ChatServer2，并重启服务端。
2026-10-02 已对本地 `127.0.0.1:3306/cppchat` 执行数据库迁移，确认两个
`tags` 字段均为可空的 `utf8mb4 TEXT`，服务端配置的应用账号也可以读取。
客户端和服务端尚未编译、重启或联调。
没有新增 gRPC 消息；跨服好友通过通知在接收方 ChatServer 查询其所属账号的标签。

### 协议

| 接口 | 消息编号 | 字段 |
| --- | --- | --- |
| 好友申请 | 1009 | 原字段 + `tags: string[]` |
| 接受申请 | 1013 | 原字段 + `tags: string[]` |
| 好友通过回包/通知 | 1014 / 1015 | `back`, `tags` 为接收者自己的备注与标签 |
| 保存已有好友备注和标签 | 1038 | `friend_uid`, `request_id`, `tags: string[]`，可选 `back: string`（最多 64 个字符；空串清除，省略则保留） |
| 保存回包 | 1039 | `error`, `friend_uid`, `request_id`；成功附带标准化后的 `tags` 及确认保存的 `back`（请求提供时） |

保存已有好友标签时，服务端从已登录的 TCP 会话取得操作人 uid，校验好友关系，
使用参数绑定更新该操作人的好友记录。空数组用于清空标签；重复保存相同值也成功。
保存请求带唯一编号；超时重试后，旧请求的晚到回包不会覆盖本次修改。

### 验证场景

1. A 申请 B，设置“同学”；B 接受并设置“家人”。双方的资料分别显示各自的标签。
2. 同服、跨服以及对方离线后上线，均检查标签；退出后重新登录，内容仍一致。
3. 给已有好友修改标签、清空标签、重复保存相同值，再重新登录检查。
4. 切换账号，确认不会读取其他账号的标签。
5. 网络失败、保存超时或数据库失败，原显示内容保持不变，弹窗能够重试。
6. 标签编辑期间好友被删除，弹窗关闭；重新添加后不恢复已删除关系的标签。
7. 直接提交非数组、超量、超长或含控制字符的标签，服务端拒绝；伪造操作人 uid
   无法修改其他账号的好友记录。

<a id="delete-friend"></a>

## 删除好友

入口：通讯录 → 点击好友 → 联系人资料 → 删除好友。

确认后，服务端在同一个 MySQL 事务中删除双方的 `friend` 关系及双方的
`friend_apply` 记录。`private_chat`、`chat_thread`、`chat_message` 保留；重新
申请并通过好友后沿用原私聊会话，重新加载历史记录。

请求中的 `friend_uid` 是要删除的好友；操作人的 uid 来自已登录的 TCP
会话。重复删除会成功返回，便于网络超时后重试。数据库失败或请求超时
时，客户端保留好友并显示错误，支持重试。

在线同步：同服直接 TCP 通知，跨服通过新增 gRPC `NotifyDeleteFriend`
通知。客户端心跳核对数据库好友快照，补齐跨服通知失败时的删除状态。
心跳使用请求编号及发送时的好友对象快照，避免旧回包误删刚添加的好友。

客户端清理联系人、好友申请、私聊列表、未读标记、对应草稿及上传任务
的聊天回调，关闭已删除好友的聊天输入；晚到的历史记录和消息不会恢复
该会话。服务端的发送、创建私聊和读取私聊历史接口均校验当前好友关系。

协议：

| 接口 | 编号 | 字段 |
| --- | --- | --- |
| 删除请求 | 1035 | `friend_uid` |
| 删除回包 | 1036 | `error`, `friend_uid` |
| 删除通知 | 1037 | `error`, `uid`, `friend_uid` |

错误码 `FriendNotFound = 1017`：你们已不是好友，请重新添加好友后再聊天。

部署时重新编译 Qt 客户端、ChatServer、ChatServer2。两份 ChatServer 的
Protobuf/gRPC 文件均已重新生成，新功能无需修改数据库表结构。

使用测试账号验证：取消确认、同服删除、跨服删除、对方离线后再登录、
删除时正在加载历史/上传图片、网络超时重试、重新添加后恢复历史。
特别检查：删除后双方均无法用旧 `thread_id` 再发送文本或图片消息。

## 聊天截屏

### 使用

1. 登录并打开好友会话，点击输入框工具栏的剪刀按钮。
2. 聊天窗口暂时隐藏，在显示器上拖动鼠标框选。
3. 拖动选区内部可以移动选区；点击「重新框选」重新选择。
4. 点击「完成」、按 Enter 或双击选区，将截图插入当前输入框。
5. 检查草稿，再点击「发送」。Esc、右键或「取消」退出截屏。

支持在任一显示器上框选；一次选区限于一个显示器，不能跨屏。
框选阶段显示原始屏幕的快照，尺寸标注使用实际图片像素。

### 代码职责

- `widgets/screencapture`：隐藏/恢复聊天窗口、获取各屏幕原图、框选遮罩及确认/取消。
- `dialogs/chatpage`：检查当前会话，调用截屏，将确认结果插入草稿；退出登录或切换会话时取消截屏。
- `widgets/MessageTextEdit`：将截图编码为 PNG，复用图片草稿、撤销和附件校验。
- `style/pages/dialogs.qss`：截屏确认工具栏的样式，随现有主题一起加载。

每个显示器使用独立遮罩窗口，按原图尺寸与逻辑坐标的比例裁剪，保留实际像素。
PNG 编码采用无损保存；输入框中的小图只用于预览，上传使用完整数据。
图片继续受现有 20 MB 限制，超过限制时提示错误，不插入草稿。
确认前图片只保存在内存中，不写临时图片文件、不修改系统剪贴板、不自动上传。
点击发送后沿用现有 ResourceServer 上传和聊天图片消息流程，无需新增服务端协议。

截屏实现使用 Qt 的 [QScreen::grabWindow](https://doc.qt.io/qt-6.5/qscreen.html#grabWindow)。
坐标处理参考 Qt 的[高 DPI 说明](https://doc.qt.io/qt-6.5/highdpi.html)。
